# Android 稳定性收尾与独立仓库计划

日期：2026-10-05。当前阶段只规划与核对边界；尚未创建远程仓库或删除原仓库文件。

## 一轮 bug 搜寻

这一轮以阅读器为中心，覆盖图书馆入口和相关 App 生命周期，不扩大为全 App 重构。
先固定当前可用版本作为回退点，再逐项记录实际操作、预期、实际结果、日志与修复验证。
优先人工真机操作，自动测试补充已定位的逻辑；不恢复此前失效的 E2E 操作脚本。

| 优先级 | 范围 | 操作与检查 |
| --- | --- | --- |
| P0 | 加载和取消 | 冷开 EPUB/DOCX/TXT/PDF；加载中退出、换书、切后台；连续快速跳转，只显示最后目标；失败可退出和重试，没有永久转圈 |
| P0 | 跳转与位置 | 进度条拖到开头、中间、末尾；目录、搜索、脚注、书签互相跳转；检查目标、进度同步和预热是否继续 |
| P1 | 手势和边界 | 慢拖、取消拖动、快速连翻、反向拖动、跨短章节；连续滚动跨节；动画中打开工具或切模式，检查断触、重复提交和错页 |
| P1 | 文档兼容 | 普通图片、SVG 封面、图片独占章节、脚注、表格、长段落；检查裁切、空白、蓝色背景、加载失败和重试 |
| P1 | 保存和恢复 | 图片页和文字页分别保存；退出重开、后台恢复、修改字号/行距/主题、切阅读模式，位置保持合理 |
| P1 | 网络和缓存 | 已缓存书离线阅读、未缓存资源断网后恢复、资源版本变化、预热时跳转；不破坏开书权限验证与阅读计时规则 |
| P2 | 图书馆与资源 | 列表首屏位置、滚动、进入返回、重复开关书；检查崩溃、持续内存增长、重复请求和残留任务 |

每个修复独立记录。检查期间不同时更换阅读引擎或重做 UI，便于定位回归。
性能只报告有真机证据的结果，编译和单元测试通过不代表手感达标。

退出条件：没有未处理的 P0；上述人工操作逐项有结果；已有问题复现用例回归通过；
已知 P1/P2 如未修复需明确列出。交付 APK、对应源码包、bug 清单和验证记录。

## 独立仓库边界

建议仓库名 `CustodySim-Android`，以当前 `android/` 内容作为新仓库根目录，保留
`app/`、`episteme-core/`、`readerbenchmark/`、Gradle wrapper、版本目录和许可证。
现有仓库继续维护 Web、服务端、数据库和部署，二者通过现有 HTTP API 协作。
App 包名、签名配置方式、版本规则和本地数据格式维持现状，便于覆盖安装。

新仓库整体发布按 AGPL-3.0-only 管理。已有 MIT 授权、版权和第三方许可继续保留，
包括 `LICENSES/CustodySim-MIT.txt`，不通过拆仓抹掉原有授权或归属信息。
原仓库维持 MIT；独立仓库本身并不改变代码组合与分发产生的许可义务。

已确认的跨目录依赖需要一并迁移并改路径：

- `scripts/vendor-episteme-core.mjs` 及其上游检查目录约定。
- `scripts/generate-reader-benchmark-fixture.mjs`。
- `scripts/run-reader-benchmark.ps1`、`scripts/promote-reader-profile.mjs` 中 App 根目录约定。
- Android 集成、性能、客户端说明，以及适用于独立仓库的 AGENTS.md。
- `androidCorrespondingSource` 当前引用父目录 LICENSE、scripts 和 docs 的路径。
- App 内对应源码获取说明、链接及发布包名称。

## 拆仓执行顺序

1. 稳定性收尾后固定迁移版本。当前工作区存在大量已修改及未跟踪文件，先清点并
   将属于 App 的最新修复纳入迁移快照；只过滤提交历史会遗漏未提交修复。
2. 在独立副本中按 Android 路径及必要脚本/文档导出历史，保留版权、作者和来源。
   不在原仓库运行破坏性历史过滤。记录新旧提交映射和上游导入 provenance。
3. 将 Android 构建目录提升为新仓库根，迁入必要工具和文档，修复路径。
   自包含构建、测试、源码打包均不依赖旧仓库或本机 inspection checkout。
4. 新仓库从干净 checkout 验证 dev APK、阅读器单元回归、lint 和对应源码包。
   发布构建、签名和基线 profile 单独核对，不把 dev 编译结果当作 release 验证。
5. 审核源码包和历史是否含凭证、私有配置、签名材料、缓存及生成文件。
   新仓库配置自身 CI；建立 APK 与对应源码的同版本发布流程。
6. 新仓库可构建、可发布且接现有服务端通过后，原仓库当前分支移除迁走的 App
   目录及专用工具，并在 README 链接新仓库。保留原历史和明确的迁移来源。

拆仓验收：新目录独立构建；原 Web/服务端构建不受影响；覆盖安装保持数据；
API 契约未变；许可声明、依赖归属和同版本对应源码可获得。
远程仓库的所有者、准确名称及公开性在真正创建前确定。
