# 操作审计

管理员从「安全与审计 → 操作审计」查看记录。页面默认显示最近七个上海自然日，可按关键词、操作人类型、操作类型、业务对象类型和日期筛选；关键词搜索操作名称、操作人及日志或对象 ID。筛选由服务端执行，不局限于已加载的页面。需要更早记录时，调整日期或选择不限日期。

点击一条记录查看执行时间、身份、对象、日志 ID 和业务详情，支持查看前后值、维护备份标识、相关任务等已记录内容，也可按对象 ID 继续查找。字段名称中的密码、令牌、密钥等凭据在详情响应中隐藏；原始记录不因此改写。记录详情按需读取，列表不传输完整 JSON。

真人用户、AI 系统和系统任务分别标识；未知业务类型或身份类型保留原始值，不猜测为真人。审计是只读页面，没有删除、修改或导出功能。默认保留期为 730 天，空列表与加载失败分别显示；审计只能展示已写入的操作，不能据此证明所有业务活动均已被完整记录。

分页按 createdAt、id 倒序，游标保留 PostgreSQL 微秒精度，避免仅使用 JavaScript 毫秒时间导致漏行。接口列表 /api/audit-logs 和详情 /api/audit-logs/[id] 均仅管理员可访问，非法筛选或游标返回 400。审计页当前筛选仅保存在本页状态中。

## 审计查询与部署

2026-11-01：分页使用 `(created_at,id)` 元组比较，配套 `audit_logs_created_id_idx`；关键词对操作者、操作标签、操作代码、业务类型及两个 UUID 拼接后的元数据搜索，配套 `pg_trgm` GIN 表达式索引。关键词转义 `%`、`_` 和反斜杠；不搜索详情或凭据。

`scripts/deploy.sh` 调用 `upgrade-audit-indexes.mjs`：默认只读检查，执行必须显式指定 `--apply --database=<实际库名>`，并校验连接目标；并发建索引、校验定义及有效性，支持重复执行和 `--rollback`（只移除这两个索引，保留扩展）。数据库账号需要安装 `pg_trgm` 的权限，或由管理员预先安装。索引无效时需先显式回滚，再重建。

默认最近七天以缩小范围；一两个字符的关键词可能无法提取有效 trigram，大范围搜索仍可能扫描较多行，不能承诺所有筛选都走索引。
