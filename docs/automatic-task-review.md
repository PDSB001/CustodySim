# GLM 自动任务审核

服务端每分钟扫描已提交任务，每批最多 3 个，串行请求智谱官方 `glm-4.1v-thinking-flash`。仅对明确启用的模板处理，模型不能获得人员档案、账号、历史积分；发送模板要求和本次模板字段的回答。回答本身如果包含个人信息，仍会传给智谱，因此只启用适合外部模型处理的模板。

## 启用

1. 部署前用项目现有 `pnpm db:push` 同步 `auto_review_runs` 和 `auto_review_settings` 表，备份流程沿用现有部署规范。本次开发只同步了 `custodysim_e2e`。尚未升级时，管理页显示升级提示，自动审核保持关闭。
2. 在服务端 `.env.local` 配置：

```dotenv
GLM_API_KEY=你的智谱API密钥
```

3. 部署或修改服务端密钥后重启 Next.js。管理员打开侧栏“自动审核”（`/auto-review`），选择审核账号、允许处理的模板，勾选启用并保存。账号和模板从当前连接的数据库读取，生产环境会显示生产模板。页面仅显示密钥是否已配置，不读取或保存密钥内容。
4. 为所选模板填写明确的任务要求（模板 content）。审核账号必须为启用且已完成首次改密的 ADMIN/SUPERVISOR，监管人只处理其辖区人员。请使用专门且可追溯的审核账号。

开关和范围保存在当前数据库，默认关闭；旧的 `AUTO_TASK_REVIEW_ENABLED`、`AUTO_TASK_REVIEW_ACTOR_ID`、`AUTO_TASK_REVIEW_TEMPLATE_IDS` 环境变量不再控制审核。保存后无需重启，下次扫描（最多一分钟）读取新设置，符合条件的已有待审核提交也会处理。关闭或更改范围后，尚未应用的旧模型结论会转人工；审核事务与设置更新通过数据库锁排序，关闭保存成功后旧结论不会再提交。设置变更与审计在同一事务中保存，多管理员同时编辑发生冲突时须刷新。

官方接口固定为 `https://open.bigmodel.cn/api/paas/v4/chat/completions`，不自动切换到收费模型或其他服务商。官方免费模型说明：https://docs.bigmodel.cn/cn/guide/models/free/glm-4.1v-thinking-flash 。免费额度、并发和可用性仍以服务商实际规则为准。未配置实际密钥前，不进行真实模型联调。

## 决策与降级

- 先检查模板、必填、字段类型和抄写一致性。无明确要求、图片或禁闭检讨保留人工审核。
- 模型返回结构化结论：通过、退回、人工。模型置信度低于 0.9、结论矛盾或退回证据无法在原回答找到时，转人工。置信度是模型自报，不能视为准确率保证，启用前应对实际模板抽样核验。
- HTTP 错误、限流、超时、JSON 异常或输出截断不改变任务状态，不循环重试；人工审核队列显示降级原因。
- 通过／退回复用人工审核事务，包括印章、计分和审计。用户可看到退回说明。禁闭检讨不由模型决定。
- 每个提交版本只领取一次；网络调用不持有数据库事务锁；返回后重查权限、任务状态、时间戳和内容，旧结论不会覆盖取消、人工审核或新提交。中断超过 5 分钟的运行转人工。
- 未满足自动审核条件的任务沿用原来的截止和逾期规则；不会因为等待模型自动延长截止时间。

## 验证

`pnpm test` 运行规则和模型响应契约测试；`pnpm test:e2e:business` 在独立数据库验证自动通过／退回、失败降级、重复扫描、取消及内容并发修改。测试中的 GLM 响应由受控替身提供，不向外部服务发送测试或业务内容。真实模型的审核质量仍需配置密钥后用允许外传的样本验证。

## 免费模型联调结果

GLM-4.7-Flash 与 GLM-4.6V-Flash 实测返回 429 / 1305。GLM-4-Flash-250414 虽可调用，但指令注入样本曾被错误通过，因此未采用。当前改用 GLM-4.1V-Thinking-Flash，仍只发送文本；图片继续人工审核。新模型的跑题样本可能因低置信度转人工，不降低 0.9 阈值来追求自动退回。明确的现场核验和负责人签字要求由程序先行转人工。少量虚构样本只证明基础链路和部分边界，不代表对所有提示注入或真实业务具有稳定准确率。
