# GLM 自动任务审核

模型请求会独占数据库会话连接。`GLM_REVIEW_MAX_CONCURRENCY` 还受连接预算约束：所有模型合计最多占 Web 池的四分之一，且最多 5 条；池小于 4 时暂停模型审核。无槽时待审项等待后续扫描，人工审核始终可用。

连接预算为零时，管理页显示“模型审核暂停”及原因，服务端对暂停状态去重告警；配置恢复后清除暂停状态。暂停不新建自动审核记录、不改变任务或补卡的待审状态，也不阻止网站启动。连接预算按 Web 进程计算，同服务商/模型的并发另由 PostgreSQL 锁跨进程限制；扩容仍需核算数据库总连接数。

服务端每分钟扫描待审核任务，每批最多 3 个，串行请求所选智谱服务商。默认保留原 BigModel 地址及 `glm-4.1v-thinking-flash`；管理员可切换至 z.ai 的 `glm-4.5-flash`。同一服务商和模型的请求使用 PostgreSQL 会话级 advisory lock 跨进程限制并发；默认按余额 API 上限配置：`glm-4.1v-thinking-flash` 为 5、`glm-4.5-flash` 为 2、`glm-4.7-flash` 为 1，其他模型保守设为 1。若账号属于 Coding 套餐或权益不同，可用 `GLM_REVIEW_MAX_CONCURRENCY` 按其套餐权益覆盖。没有可用并发槽时本轮暂缓，留待后续扫描，不会占用审核记录。每次模型调用最多等待 60 秒；超时或输出截断转人工。任务审核与补卡审核各最多串行处理 3 项，过期运行在 10 分钟后回收为人工审核。仅对明确启用的模板处理，模型不能获得人员档案、账号、历史积分；发送模板要求和本次模板字段的回答。回答本身如果包含个人信息，仍会传给所选服务商，因此只启用适合外部模型处理的模板。

## 启用

1. 手动部署会在 `scripts/deploy.sh` 中幂等创建审核表，并将现有设置的服务商默认补为 `bigmodel`；不需要手工 `db:push`。独立更新数据库时可运行 `node scripts/upgrade-auto-review.mjs --database=<数据库名>`。尚未升级时，管理页显示升级提示，自动审核保持关闭。
2. 在服务端 `.env.local` 配置：

```dotenv
GLM_API_KEY=your-existing-bigmodel-key
ZAI_API_KEY=your-z-ai-key-if-selected
```

3. 管理员打开任务编排中的“自动审核”标签，选择服务商、审核账号和模板，按需开启任务或补卡审核并保存。账号和模板从当前数据库读取。页面仅显示密钥是否已配置，不读取或保存密钥内容；服务商切换立即生效，无需重启。
4. 为所选模板填写明确的任务要求（模板 content）。审核账号必须为启用且已完成首次改密的 ADMIN/SUPERVISOR，监管人只处理其辖区人员。请使用专门且可追溯的审核账号。

开关和范围保存在当前数据库，默认关闭；旧的 `AUTO_TASK_REVIEW_ENABLED`、`AUTO_TASK_REVIEW_ACTOR_ID`、`AUTO_TASK_REVIEW_TEMPLATE_IDS` 环境变量不再控制审核。保存后无需重启，下次扫描（最多一分钟）读取新设置，符合条件的已有待审核提交也会处理。关闭或更改范围后，尚未应用的旧模型结论会转人工；审核事务与设置更新通过数据库锁排序，关闭保存成功后旧结论不会再提交。设置变更与审计在同一事务中保存，多管理员同时编辑发生冲突时须刷新。

默认接口保留 `https://open.bigmodel.cn/api/paas/v4/chat/completions` 与原来的 `glm-4.1v-thinking-flash`，升级后既有部署继续使用原密钥。管理员可在页面切换到 z.ai；此时使用 `https://api.z.ai/api/paas/v4/chat/completions` 与 `glm-4.5-flash`，不会切换到收费 FlashX。官方定价：https://docs.z.ai/guides/overview/pricing 。

密钥按服务商隔离，不会互相回退或转发。切换前需在服务端配置对应密钥；更换服务器密钥后重启服务。没有配置时无法保存开启状态，扫描也不会外发内容。

补卡审核为独立开关，默认关闭。纯文字理由能理解、与漏打卡相关即可基本通过，允许简短口语化及日常原因，不额外要求详细时间、完整经过、证明材料或解释补卡必要性。含图片凭证或无法理解的理由转人工，空白、完全无关或无意义内容不合格。补卡操作受所选审核账号监管范围约束。

补卡待审卡片直接显示自动审核转人工原因；“审核轨迹”可查看自动审核结果、原因、配置模型与时间，以及后续人工审核人的决定和意见。配置模型仅表示该次运行的配置，本地规则转人工时不会调用模型。人工处理后，原自动审核原因仍可在“批阅记录 → 补卡记录”查看；重新申请的旧记录标为“历史申请”，不再作为当前待审提示。最终审核显示处理时间，未填意见时明确标注。轨迹复用已有自动审核表与审计记录，无新增数据库迁移；可见范围与补卡队列一致，审计记录受既有日志保留策略约束。

## 决策与降级

- 先检查模板、必填、字段类型和抄写一致性。无明确要求、图片或禁闭检讨保留人工审核。
- 内容基本覆盖核心要求即可通过，不因简短、口语化、轻微错字或不影响理解的细节遗漏提高门槛，不额外要求模板未列明的字数、完整流程、深入反思或改进计划。
- 模型返回结构化结论：通过、退回、人工。通过门槛为 0.8，退回仍为 0.9；低于对应门槛、结论矛盾或退回证据无法在原回答找到时转人工。置信度是模型自报，不能视为准确率保证，启用前应对实际模板抽样核验。
- HTTP 错误、限流、超时、JSON 异常或输出截断不改变任务状态，不循环重试；人工审核队列显示降级原因。
- 通过／退回复用人工审核事务，包括印章、计分和审计。用户可看到退回说明。禁闭检讨不由模型决定。
- 每个提交版本只领取一次；网络调用不持有数据库事务锁；返回后重查权限、任务状态、时间戳和内容，旧结论不会覆盖取消、人工审核或新提交。中断超过 10 分钟的运行转人工。
- 宽松标准用于部署后的新审核；既有自动审核记录与人工决定保持原样，不会自动重跑已经转人工的同一提交版本。
- 未满足自动审核条件的任务沿用原来的截止和逾期规则；不会因为等待模型自动延长截止时间。

## 验证

`pnpm test` 运行规则和模型响应契约测试；`pnpm test:e2e:business` 在独立数据库验证自动通过／退回、失败降级、重复扫描、取消及内容并发修改。测试中的 GLM 响应由受控替身提供，不向外部服务发送测试或业务内容。真实模型的审核质量仍需配置密钥后用允许外传的样本验证。

## 免费模型联调结果

此前国内站联调中，GLM-4.7-Flash 与 GLM-4.6V-Flash 返回过 429 / 1305。GLM-4-Flash-250414 虽可调用，但指令注入样本曾被错误通过，因此当时采用 GLM-4.1V-Thinking-Flash。该记录不能代表 z.ai 当前账号的可用性。切换后须用虚构或允许外传的样本验证连通性、耗时和审核质量；本地模拟测试不等于真实模型验收。仍只发送文本，图片继续人工审核，自动退回维持 0.9 门槛。明确的现场核验和负责人签字要求由程序先行转人工。
