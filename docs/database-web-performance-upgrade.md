# Web 性能数据库升级

部署入口仍然只有 `scripts/deploy.sh`。此次只新增索引，不改列、不删记录；业务数据库尚未执行升级。

```bash
# 只读检查，不拉代码、不构建、不重启
bash scripts/deploy.sh --check-db

# 正常部署：拉代码、装依赖、构建、复制静态资源、升级索引、重启、自检
bash scripts/deploy.sh

# 显式回滚本轮新增索引，不重启、不撤销业务数据
bash scripts/deploy.sh --rollback-db
```

## 新增索引

| 索引                                    | 字段                                        | 对应查询                                   |
| --------------------------------------- | ------------------------------------------- | ------------------------------------------ |
| `persons_created_id_idx`                | `created_at, id`                            | 人员列表稳定排序和分页                     |
| `chat_messages_conversation_cursor_idx` | `conversation_id, created_at DESC, id DESC` | 消息时间相同情况下的游标分页、会话最新消息 |
| `chat_messages_sender_created_idx`      | `sender_id, created_at`                     | 发送频率限制的短时间窗口计数               |

索引已同步到 Drizzle schema；升级 SQL 保存在 `lib/db/upgrades/20260925-web-performance.*.sql`。脚本内部调用 Node/pg 执行器，部署机器无需额外安装 psql。没有接入全量 `drizzle-kit push`，避免这次性能发布顺带执行其他结构变更。

## 执行行为

- 连接当前部署配置的 `DATABASE_URL`，校验实际数据库名与 URL 中声明的一致，不打印连接串。环境变量优先于 `.env.local`；与 Node 执行器保持一致。
- 使用 `CREATE INDEX CONCURRENTLY`，逐条执行，不包事务。需要表所有者或具备相应权限的数据库角色，会消耗额外 I/O 和索引存储空间。
- 通过数据库 advisory lock 阻止同一升级的并发执行；锁等待上限 5 秒，单条索引操作上限 30 分钟。
- 重复部署跳过已存在且定义正确的索引。发现同名异定义索引或无效索引会停止；无效并发索引可先通过 `--rollback-db` 清除本轮索引，再重新部署。异定义冲突需要人工核对。
- 中途失败可能留下部分已建索引；脚本报错并停止，不进入 PM2 重启。不要把并发 DDL 放进外部事务。
- 重启使用 `ecosystem.config.cjs`，加载更新后的环境配置；自检检查登录页、静态资源、未登录 API 的 401 和实时服务 health，失败返回非零退出码。
- 索引回滚只影响性能，当前应用代码不依赖这些索引才能运行。下一次正常部署会重新创建它们。`--rollback-db` 会删除本轮三个已存在的匹配索引，操作前应确认确实需要撤销此次优化。

## 验证与配套优化

- 已在独立 `custodysim_e2e` 测试库验证索引创建、重复执行和回滚，并恢复测试前索引状态。
- 当前配置的 `custodysim` 数据库仅执行了 `--check-db`，三个索引均显示 `missing`，没有执行升级或部署。
- 聊天已读人数改为数据库按消息聚合，最多返回当前页消息数的统计行，仍只统计被监管用户。相同时间戳的 52 条消息测试验证分页无重叠、无遗漏。
- 会话成员分组改为数组追加，避免不断复制已有成员数组。
- 档案字段 schema 独立于编辑器模块，编辑器动态加载，列表解析不再静态引用编辑器。
- 185 项单元测试、5 项本轮相关数据库集成测试、TypeScript、全量 ESLint、生产构建通过；部署脚本通过 Bash 语法检查。
- `node scripts/test-deploy-flow.mjs` 用替身命令验证了 5 种部署流程：正常部署、升级失败禁止重启、自检失败返回非零、只读检查、索引回滚。该测试不操作真实数据库或 PM2。未执行完整生产部署，未实测生产查询延迟降幅。
