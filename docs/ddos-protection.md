# 源站与应用层防护

本站使用 EdgeOne 回源认证和访客 IP 条件映射。私有配置中的回源密钥不得提交到仓库。
CDN 接入本身不保证源站隔离；本方案也不能代替云平台的带宽型 DDoS 防护。

## 部署

先在 EdgeOne 配置回源密钥头与 `EO-Client-IP`，并在 Nginx 私有配置中维护
`$custodysim_edgeone_authenticated` 和 `$custodysim_client_ip` 两个映射。
只有密钥正确才采用 `EO-Client-IP`，否则使用连接来源地址。
不要直接相信公网传入的 `X-Forwarded-For`。

首次启用通过部署脚本，显式指定站点：

```sh
git pull --ff-only
EDGEONE_NGINX_SITE=/etc/nginx/sites-enabled/custodysim bash scripts/deploy.sh
```

安装器先备份到 `/etc/nginx/custodysim-backups/`，仅启用诊断日志，实际通过公开域名发起请求，
确认回源认证成功且访客 IP 是独立有效的公网地址，再启用拦截与限流。任何验证失败都会恢复原配置。
后续部署无需再次设置该变量；已有配置会保留。所有 Nginx 修改先执行 `nginx -t` 再 reload。
如需手工回滚，将备份目录中对应的站点、HTTP 配置和 snippet 还原至原路径；首次新增的后两者应移除，
执行 `sudo nginx -t && sudo systemctl reload nginx`。备份位于扫描目录之外，不会被当作新站点载入。

生产 Web 和实时服务均仅监听 `127.0.0.1`，主机防火墙继续拒绝 3000/3001 的公网访问。
HTTPS 源站拒绝没有有效回源认证的外部请求；回环访问保留给本机自检。
HTTP 80 的 Certbot 验证与 HTTPS 跳转保留。

## 当前阈值

所有 Nginx 限流按还原后的访客 IP 计算；超限返回 429，不进入 Next.js/数据库。

| 流程                                           | 每 IP                      | 全站               |
| ---------------------------------------------- | -------------------------- | ------------------ |
| `/api/*`                                       | 15 次/秒，突发 60          | 60 次/秒，突发 120 |
| 页面（排除静态资源及单独保护的 API/Socket.IO） | 10 次/秒，突发 30          | 30 次/秒，突发 60  |
| 登录、注册、改密、MFA 验证、安全邮箱发码/确认  | 30 次/分钟，突发 5         | 2 次/秒，突发 4    |
| APK 下载                                       | 12 次/分钟，突发 5；并发 2 | 并发 16            |
| Socket.IO 在途请求/连接                        | 并发 64                    | 并发 768           |

密码相关接口请求体限制 16 KiB、接收超时 10 秒；管理员 APK 上传保留 256 MiB 流式上传。
一般会话查询、刷新和登出仅受通用 API 限流，不与密码计算共用严格额度。
这些是小规模部署的起始值，共享出口、多设备与重连增加时需根据日志调整；不要直接套用到其他容量的服务器。
账号失败锁定、验证码及邮件业务配额继续保留，bcrypt 工作因子保持 12。

实时服务另在认证前预留连接配额：总计 512、每 IP 32，握手每 IP 平均 30 次/分钟、突发 12，
全局平均 10 次/秒、突发 20。状态表最多 4096 个 IP，闲置记录可回收；未完成传输创建的预留 10 秒释放。
单消息 64 KiB，未加入命名空间超时 45 秒，升级超时 10 秒，心跳 20 秒、响应超时 10 秒。
实时数据库池最多 8 个连接，连接等待 5 秒、语句超时 10 秒。Web/App 现有协议不变。
同一传输连接最多允许 3 次命名空间认证尝试，防止复用已建立连接绕过握手限流、重复执行令牌验证与 SQL。

## APK 缓存

下载页动态生成带文件版本的 URL。仅匹配当前文件版本的请求返回
`Cache-Control: public, max-age=0, s-maxage=86400`；不带版本的旧链接继续每次重新验证。
错误版本返回不可缓存的 404，发布替换文件后下载页立即生成新 URL。
旧版本若已在边缘缓存可继续返回旧版本本身，不能用旧 URL 返回新文件。
ETag、Last-Modified、HEAD、单段 Range 和 If-Range 保留。

需要在 EdgeOne 控制台实际配置并验证：

1. 精确匹配 `/api/app-download/apk`，仅缓存公开成功响应；缓存键保留 `v`，不得忽略所有查询参数。
2. 此公开下载端点不按 Cookie 分片、不附带鉴权；其他 `/api/*` 继续绕过缓存。
3. 遵循源站缓存头；不要强制缓存 404、429、其他 API 或无版本的下载请求。
4. 分别验证两次相同版本下载的缓存命中、Range 与新版本链接行为。

源站响应头不能证明 CDN 规则已经启用；必须以 EdgeOne 控制台和响应缓存命中证据为准。

免费漏洞防护规则集的 17 条规则由观察改为拦截。网站级规则会影响本站后续新增域名，接入新业务时须复核。

已发布 `CustodySim APK 版本缓存`，精确匹配主站公开 APK，遵循源站缓存头、无缓存头不缓存，
缓存键保留完整查询字符串（包括 `v`），不按 Cookie 分片；关闭离线缓存，并将错误状态码缓存设为 0 秒。
可复用配置见 [apk-cache.json](../deploy/edgeone/apk-cache.json)，在控制台以“创建规则”导入，
不要用它覆盖包含私有回源密钥的既有站点规则。当前无已发布 APK，真实安装包命中率和边缘 Range 行为留待上传后验证。

仍需确认或按套餐能力处理：

- 安全组只允许当前套餐提供的 EdgeOne 回源网段访问业务 HTTPS，并维护网段更新；SSH 保留可信运维入口。
- 在边缘对昂贵接口配置速率限制与实际拦截动作，并检查 WebSocket 支持、WAF 和例外规则。
- 配置流量、请求量、带宽和费用告警；告警不等于硬性费用封顶，需另确认套餐是否支持。

`/var/log/nginx/custodysim-security.log` 记录可信客户端 IP、连接来源、回源认证标记、路径、状态和限流结果，
不记录密钥、Cookie、令牌或完整查询字符串。标准 access.log 也保留；随系统 Nginx 日志轮转。
通过 429 数量、认证拒绝数量、数据库等待和主机资源趋势调整，不在生产进行洪泛压测。
