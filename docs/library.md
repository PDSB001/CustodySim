# 图书馆

- 管理端 `/library` 上传、上架或下架 PDF、DOCX、EPUB 和 UTF-8 TXT（最大 20 MB）。原文件以 PostgreSQL `bytea` 保存，DOCX/EPUB 上传时提取的正文也持久化；书籍下架不删除历史数据。
- Web 管理端和 App 管理员图书馆均有“图书管理、阅读任务、阅读积分”入口。支持编辑书名作者、更换电子书和封面、上下架、移出书架；移出采用软删除，保留文件与阅读历史但所有角色的列表和阅读端点均隐藏该书。替换正文会结束旧会话并将现有页码重置为 1，累计时长仍保留。
- 双端显示真实封面。可上传 3 MB 内的 PNG/JPEG/WebP；服务端解码、限制像素、压缩为 JPEG 并以 `bytea` 持久保存。EPUB 2/3 内置封面和 DOCX 缩略图自动提取，之前导入的 EPUB/DOCX 首次请求封面时会补提取。未提供或无法提取时明确显示缺省占位，管理员可随时补封面。
- 管理员可在图书馆内直接创建每日阅读任务、编辑分钟要求与启停，设置下发时间、任务有效时长和个人/任务组范围。全体选项覆盖创建时现有被监管人并保存明确成员范围；空范围不会被误标为全体。每日规则从下一个上海时间下发时刻生效，避免创建已过期的历史任务。已生成任务保留原快照，设置修改仅影响后续下发。
- DOCX/EPUB 支持正文重排阅读，不保留图片、表格样式或复杂排版。EPUB 按 spine 顺序读取章节，不执行脚本，暂不支持 DRM 加密文件；PDF 保留页面排版。
- Web `/my/library` 和 `/supervisor/library`；Android 首页列表和各主页面右上角图书入口。入口常驻，无需有学习任务。两端按页保存阅读位置，重排正文每页 2000 个 Unicode 字符。
- 阅读页使用小字号显示已保存时长，可手动暂停。Web 失焦/隐藏、App 非 RESUMED 时暂停；每 15 秒提交心跳。服务器只接受不超过 25 秒的连续片段，离线期间不补记。
- 同一用户开始新阅读会话会关闭旧会话，用户行锁防止跨设备并发计时。计时衡量阅读页前台停留，不能证明用户确实理解内容。
- 在后台“任务编排”选择学习类，直接设置“阅读时长要求（分钟）”，无需创建表单模板。生成任务保存 `completionMode=READING` 和分钟要求的快照；后台修改规则不会影响已经生成的任务。仅累计任务开始到截止的有效阅读片段，心跳达到时长就自动标记 APPROVED，无需提交或人工批阅。任务生成、查询和调度会再次核对已保存时长，避免服务重启遗漏。自动学习任务不走请假免提交逻辑。
- 旧任务没有自动阅读标记时继续沿用原提交流程。已有模板的阅读要求也可用于后续新任务。
- 阅读积分默认开启：每 15 分钟 +1 分，每个上海日期最多 3 分。管理端图书馆可开关和调整分钟要求，上限最多 3 分。积分仅为被监管人结算，Web/App 共用当天额度，积分流水来源 `READING_DURATION`。学习任务通过按原任务规则另计 2 分（退回后通过 1 分），来源 `TASK_OUTCOME`。两种记分与阅读记录在同一事务中提交，用户行锁和来源唯一约束防止重复奖励。

## 升级部署

先备份数据库，依次执行 `lib/db/upgrades/20261004-library.up.sql`、`lib/db/upgrades/20261004-library-reading.up.sql`、`lib/db/upgrades/20261004-library-management.up.sql`。脚本可重复执行，不会替换已有电子书。已部署前两版图书馆的环境只需补执行缺少的脚本。若按现有流程 `pnpm db:push` 升级，积分配置表为空时服务端会使用默认的 15 分钟/1 分、每日 3 分策略，管理员保存设置后持久化配置。

部署 Web 服务并更新 Android App。Nginx/网关须允许至少 26 MB 请求体，例如在对应 server 配置 `client_max_body_size 26m;`。Next.js 的代理缓冲已设置为 26 MB，以容纳电子书和封面同时上传。

数据库备份须包含 library_books、reading_sessions、reading_ticks、reading_progress、library_score_settings、rules、report_templates 和 score_events。电子书不依赖发布目录或临时磁盘。PDF.js worker、CMap、字体及 WASM 资源已配置 standalone 文件追踪。
