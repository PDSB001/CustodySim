# 通知与合并公示

正式通知仍在 `/notices` 管理，受众在 `/my/notices` 或 `/supervisor/notices` 查看。列表默认显示标题、优先级、对象、发布时间、有效期和两行摘要；正文与人员明细按需展开。支持服务端关键词搜索、未读/重要/紧急筛选，以及对当前已加载通知批量确认已阅。

## 系统通知的合并规则

| 事件     | 合并范围       | 保留内容                                        |
| -------- | -------------- | ----------------------------------------------- |
| 禁闭决定 | 同一考核周     | 人员、触发积分、执行起止时间、撤销/执行完毕状态 |
| 周结更正 | 同一考核周     | 人员、校正后积分、撤销原因                      |
| 检讨汇报 | 同一上海自然日 | 每份通过审核的检讨、人员、通过时间              |

通知与禁闭令/审核结果在同一事务中写入。聚合键有唯一索引，事务锁避免并发覆盖名单；重跑同一事件不重复插入。合并通知增加或变更明细时，原已读状态会清除，提示重新阅读。浏览器确认已阅携带 `updatedAt`，若阅读期间通知发生变化，服务端返回 409，要求刷新后重读。旧 App 的单条确认接口仍可使用，完整纯文本正文继续下发。

管理员下架合并公示后，后续追加明细不会自动恢复发布。已归档的原通知不能直接恢复发布，应管理对应的合并公示。

## 历史整理与部署

两个部署入口都会准备 `aggregation_key`、`metadata` 字段，并执行幂等历史整理。只处理可见、面向全体的已识别旧禁闭公示/更正/检讨，已过期、已下架及不匹配格式的普通通知不重新发布。原通知不删除，保留正文和已读记录，转入管理页「查看归档原通知」；合并公示保留原记录 ID。全部原通知都读过的用户才继承合并已读状态。原记录仍遵守系统既有通知保留期。

需要单独检查时，在仓库根目录使用 Bash：

```bash
# 将 custodysim 替换为实际数据库名；脚本会校验连接目标。
node scripts/upgrade-notice-groups.mjs --database=custodysim

# 只预览可合并的原通知数量、分组数量，不改业务记录。
pnpm exec tsx scripts/merge-notice-history.ts --database=custodysim

# 执行合并与归档；可安全重复执行，原通知及其已读记录保留。
pnpm exec tsx scripts/merge-notice-history.ts --database=custodysim --apply
```

数据库凭据从 `.env.local` 读取，不在命令行传递连接串。升级先于新版本服务重启；通知页面和 API 需要新字段就绪。

Android 通知列表同步支持合并公示与版本校验；前台直达、友盟离线推送和私有配置见 [App 推送接入与部署](app-push.md)。
