# Web 自由注册与首周考察

- 登录页提供 `/register`；App 继续使用已有账号登录，不提供注册入口。新账号固定为被监管人，不能通过请求参数选择角色、组织或考察结果。
- 默认开放注册。管理员在 `/registration` 可暂停、选择默认监室、查看考察结果和管理邮箱黑名单。未指定监室时，首次注册会自动创建“自主注册 → 注册编制 → 新用户监区 → 新用户监室”。
- 注册时创建普管、在押人员档案。默认打卡方案沿用现有规则，不生成注册时间以前的打卡和规则任务。已有账号不参加新用户考察。

## 首周口径

自注册次日起计算七个完整的上海自然日。例如 10 月 25 日注册，考察期为 10 月 26 日 00:00 至 11 月 2 日 00:00，不会因周末注册缩短。

考察积分严格大于 0 才通过，0 分与负分均不通过。积分直接来自现有流水，跨自然周累计；延后入账的打卡日结按业务日归属，任务结果按任务排班时刻归属，阅读和人工调整按流水时刻归属。已过考察期的补录不会自动重开已经完成的考察。

截止后预留 10 分钟，先运行现有打卡日结和任务结果结算，再判定考察。后台每 5 分钟检查一次，数据库事务和唯一键保证重复执行不重复处理。未达标会停用账号、停用人员档案、增加令牌版本、撤销刷新令牌和受信任设备并关闭推送绑定，历史记录保留。

首页展示考察期限与已结算积分，截止前一天向已授权并注册设备的账号发送一次提醒；App 在线时直接投递，离线时使用友盟。未配置推送、未安装新版 App 或未授权通知时，以 Web 首页为准。

## 邮箱与黑名单

不发送验证邮件、短信。注册使用 Turnstile 人机验证。邮箱先进行 NFKC 规范化、去首尾空格、转小写，再保存 SHA-256 摘要；注册记录不保存原始邮箱，不会写入已验证安全邮箱表，也不用于找回密码。

未达标自动保存邮箱摘要到黑名单；管理员也可手工添加邮箱或“拉黑并停用”注册账号。黑名单不依赖账号外键，删号后仍保留。解除黑名单不会自动启用账号，恢复需要在现有账户与人员管理中完成。

邮箱未经验证，匹配不能证明邮箱归属，也不能防止换邮箱再次注册。注册额外使用每网络每小时 5 次的数据库原子限流，成功与失败均计数；不依赖进程内计数器。生产真实 IP 继续依赖现有可信代理配置。

## 部署与验证

现有 `scripts/deploy.sh` 已包含 `scripts/upgrade-registration.mjs --database=<目标库>`。迁移新增注册设置、考察记录、邮箱摘要黑名单及浏览器/网络限制表，重复运行不会重置开关或已有考察。

## Turnstile 配置与反滥用

1. 在 [Cloudflare Turnstile](https://dash.cloudflare.com/?to=/:account/turnstile) 创建 Managed 小组件，允许生产网站域名（例如 `www.jxydev.top`）；本地测试另建允许 `localhost` 和 `127.0.0.1` 的组件。
2. 在服务器 `.env.local` 设置 `TURNSTILE_SITE_KEY`、`TURNSTILE_SECRET_KEY`，不要提交真实密钥。Site key 会提供给浏览器，Secret key 仅供服务端 Siteverify 使用。
3. 拉取代码后运行现有部署脚本并重启 Web，管理员注册页应显示“Turnstile 人机验证：已配置”。未配置、服务不可用或校验不通过均阻止注册。
4. 通过真实浏览器完成一次验证；检查网络能访问 `challenges.cloudflare.com`。保持 EdgeOne 原有 CDN，不要为 JSON API 或 App 开启全站 HTML 挑战。

服务端检查 Siteverify 的成功结果、域名、`register` action、浏览器绑定值及五分钟有效期。失败后前端重新验证，不复用旧票据。参见 [官方服务端验证文档](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/)。

网站设置 180 天的签名 HttpOnly 浏览器标识，保存其 HMAC 摘要；每浏览器 24 小时最多注册两次。手动拉黑或首周未通过同时限制已识别浏览器，删号不会删除限制。网络按 IPv4 单地址、IPv6 /64 规范化后保存 HMAC 摘要；同一网络七天内至少三个注册账号被停用才临时限制 24 小时。真实 IP 只在验票时发送给 Turnstile，不在注册记录中保存明文。

管理员可分别解除邮箱、浏览器、网络限制，解除一种不会清除其他限制，也不自动启用账号。浏览器标识能被清除、代理能改变网络，以上是叠加防护，不能保证识别同一自然人。不采集侵入式设备指纹。

浏览器 E2E 使用隔离数据库限定的 Siteverify 预加载模拟和模拟小组件，不在应用内加入验票绕过。真实 Cloudflare 连通性与生产域名配置仍需部署后验证。

本地独立验证迁移时必须明确目标数据库名：

```bash
node scripts/upgrade-registration.mjs --database=custodysim
```

验证覆盖注册权限固定、同源限制、并发邮箱唯一、注册暂停、网络限流、注册前任务排除、跨期积分归属、到期宽限、自动停用与会话撤销、扫描幂等、删号后黑名单和提醒去重。
