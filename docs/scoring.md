# 积分规则与排班切换

新规则按上海业务日期自 2026-11-01 起生效：打卡完成 +1、补卡通过 0、缺卡 -1，每日合计最低 -4、最高 +4。系统补卡不参与计分。普通任务首次按时通过 +3、退回后按时通过 +2、到期仍未通过 -3。新日期产生的禁闭反思仍需提交及审核，但过期不再扣常规积分；此前的任务仍使用其发生日期的旧规则。

2026-10-25 至 2026-10-31 的打卡日结继续按完成 +1、补卡 -1、缺卡 -2 计算，不设置上下限。更早日结保持既有冻结边界。日结服务必须传入 dayKey，任务过期按 scheduleAt 选择规则，不能仅依据执行结算时的时间判断。规则定义在 lib/score-policy.ts；Web 和新版 App 的说明从 /api/scores 的 policy 读取。旧 App 仍可解析原有字段，但不会显示新增的每日上下限和反思豁免说明。

预设方案切换时，对同一人串行生成排班，只撤销当天未来、尚待执行且没有打卡或补卡记录的旧预设任务；保留已经发生的时段和自定义规则。切换后的新预设不能追补切换前尚未生成的过去时段。

历史失效排班修复工具为 scripts/repair-checkin-plan-overlaps.mjs，默认只读预览：

    node --env-file=.env.local scripts/repair-checkin-plan-overlaps.mjs --day=2026-10-26

核对预览后，用 --apply --confirm-database=custodysim 执行。工具仅处理旧口径日期、未归档周、没有真实打卡和补卡申请、且处于禁闭有效期内并已生成禁闭预设任务的旧预设缺卡；将其标为系统豁免，减少对应日结计分时段与缺卡数，校正原积分事件。不会发放额外人工积分，也不创建虚假到场记录。

应用在单一事务中保留时间戳命名的 custodysim_backup_overlap_* 备份 schema，存放修改前的排班、日结和积分事件，并写审计记录。已归档周或数据不一致时拒绝执行，需要单独审查；重复执行应报告零项。恢复时先核对备份和修复后状态，不能覆盖修复后的真实打卡或后续人工处理。
