# 管理人员指南：安排、审核与跟进

本文面向使用业务功能的监管人员和管理员，不要求掌握服务器命令。部署、备份和故障恢复由技术维护人员按[部署指南](deployment.md)处理。

## 角色与工作范围

监管人员主要处理辖区内事项；管理员维护组织、账号、规则并处理具备权限的审核。菜单是否出现以及能看到哪些人员，由角色、组织和监管关系共同决定。Android 以日常办理为主，管理配置与完整审核工作台优先使用 Web。

| 工作           | 监管人员 Web 常用入口 | 管理员 Web 常用入口 |
| -------------- | --------------------- | ------------------- |
| 看当日情况     | 执勤总览              | 当班总览            |
| 批阅任务       | 呈报批阅              | 任务批阅            |
| 查打卡、审补卡 | 点名记录、补点核准    | 点名记录、补卡审核  |
| 审申请         | 申请审查              | 申请审核            |
| 审档案         | 档案会签              | 档案审核            |
| 查通知与聊天   | 监所公示、通信监管    | 监所通知、聊天监管  |
| 查定位         | 位置轨迹              | 位置轨迹            |

## 管理员首次投入使用

在技术人员完成部署并提供初始管理员账号后，先在 Web 登录改密，再按以下顺序核对业务配置：

1. 在「组织架构」建立需要的组织层级。
2. 在「账户管理」和「在押档案」核对人员身份、账号状态及所属组织。
3. 在「监管关系」检查人员和监管范围，避免“能登录但看不到应处理事项”。
4. 检查「打卡规则」和「任务编排」，确认适用对象、时段、周期和表单要求。
5. 按需要配置通知、电子围栏和印章等能力。缺少相关配置时，不应假设功能已启用。
6. 用专门测试账号走一次打卡、任务提交、审核和结果查看，确认用户实际收到的安排符合预期，再扩大使用范围。

组织、规则、人员关系的改动可能影响多人。保存前核对作用范围和生效条件；是否影响已有记录以页面提示和具体规则实现为准。

## 每日处理建议

先看总览中的待办，再处理有截止时间的任务与补卡，然后跟进申请、档案和异常。总览数量用于发现待办，最终以对应记录详情为准。

### 批阅任务

打开待批阅记录，核对人员、任务要求、填报内容和图片，选择页面允许的处理结果。需要补充时，意见应写明缺什么、如何修改。操作成功后核对新状态，不要将打开详情视为完成批阅。

自动审核是单独配置的能力，默认启用情况由系统设置决定。开启前需确认模板适合外部模型处理，并抽样核验结果；技术与数据处理边界见[自动审核说明](automatic-task-review.md)。

### 审核补卡

先核对原时段、缺卡情况、补卡原因和凭证，再处理补卡申请。补卡获准与原时段内正常打卡不同，查看历史时应保留这一差别；发现记录已被其他人处理，刷新后再判断。

### 审查申请

核对类型、事由、附件与时间范围。逐级流程中，你完成本级处理并不代表申请已最终批准。请假与临时离监须以最终批复的起止时间为准；向申请人说明结果时不要仅凭中间状态。

### 档案会签

核对分卷、必填项、日期、照片和签名。需要修改时写清意见；最终审批和公章处理按当前流程执行。图片导出只是副本，不替代会签或归档动作。已归档记录需要更正时，先核实系统提供的合法处理入口，不让用户反复新建重复档案。

## 通知、聊天与位置异常

发布通知前核对标题、正文及接收范围，发布后检查展示。已阅状态表示系统记录了阅读确认，不代表相关任务已经完成。

跨监室私聊按申请理由及可见范围审核。聊天有读取和清理期限，需要正式留存的事项应按业务流程形成任务、申请或档案记录。

位置轨迹有采集时间和上传时间的差别。缺少新位置可能由权限、网络、省电或设备状态造成，先联系用户核对，不仅凭一次未上传直接认定原因。精确定位数据有保留期，历史坐标被清理后不能从界面恢复。

## 发现问题时交给谁

- 账号角色、组织归属、监管关系或业务规则不对：由有权限的管理员核对。
- 登录页打不开、多人同时收不到实时消息、上传持续失败：交给技术维护人员。
- 已提交记录需要更正：先由对应审核人员检查状态和可用操作，避免通过删除数据绕过流程。

反馈时附发生时间、受影响角色、页面、记录标识和提示，不提供账号密码或密钥。[常见问题](faq.md)列出了可以先自行检查的项目。
