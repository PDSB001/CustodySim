# Web 性能优化（2026-09-25）

> 历史实施与验证记录。版本、测试数量及设备表现按记录当时理解；当前操作入口见 [文档目录](README.md)。

## 改动

- 从点名工作台中拆出 `checkin-card.tsx` 与 `checkin-home-card.tsx`，首页不再静态依赖历史记录、补卡审核和日期选择器。
- 点名历史页日期筛选器、人员列表档案弹窗使用动态导入。档案弹窗仅在打开时挂载，加载过程中显示状态提示。
- 非待执行点名卡片停止计时；首页没有待执行任务时停止排序时钟。隐藏标签页暂停 UI 时钟，返回时立即校准时间；卸载时移除监听器和计时器。
- 通用日期显示复用 `Intl.DateTimeFormat`，减少列表渲染时的重复实例化。

## 生产构建对比

同一工作区、同一依赖，优化前后均运行 Next.js 16.3.3 生产构建。统计路由客户端引用清单关联的去重 JS 文件，包含共享代码；gzip 按文件单独压缩后相加。

| 路由       | 优化前 JS 字节 | 优化后 JS 字节 | 优化前 gzip 字节 | 优化后 gzip 字节 |
| ---------- | -------------: | -------------: | ---------------: | ---------------: |
| `/my`      |        796,716 |        622,612 |          219,539 |          175,941 |
| `/persons` |        848,304 |        847,618 |          235,856 |          236,039 |

首页关联 JS 减少约 21.9%，gzip 减少约 19.9%。人员页关联代码总量基本不变；动态导入用于推迟弹窗代码加载，不据此声称总量显著下降。

此统计不是浏览器实际传输量、LCP 或交互延迟测量。网络缓存、预加载、服务端响应与实际访问路径仍会影响用户体验。

复现命令：

```powershell
node node_modules/next/dist/bin/next build
node scripts/measure-web-bundles.mjs '/(supervised)/my/page' '/(dashboard)/persons/page'
```

## 第二轮：人员列表与档案汇总

- 人员管理页默认每页 25 人，支持按姓名、人员编号、自定义编号、账号搜索。提交搜索重置到第一页，支持清除搜索、加载提示、失败重试与无结果提示。
- API 使用 `page`、`pageSize`、`q` 参数返回 `{ items, total, page, pageSize }`。页大小限制为 1–100，搜索最长 100 字；`%`、`_`、反斜杠按字面值搜索。无这些参数时保留原数组响应，兼容旧调用方。
- 分页按创建时间与 ID 稳定排序；页码超过末页时回退到最后有效页。
- 档案汇总仅查询本页关联用户，数据库按用户与状态计数，再一次遍历归并。移除了应用层逐人扫描全部档案的 O(人数 × 档案数) 操作；保留未填写、草稿、退回、待审核、全归档的原状态优先级。
- 监室选项统一计算后复用。使用已有的用户/状态索引，无需数据库迁移。

第二轮验证：185 项单元测试、3 项测试库集成测试、桌面及移动端 2 项浏览器回归、生产构建、TypeScript 和全量 ESLint 通过。浏览器回归使用生产构建的独立 3102 端口，配置测试库及对应 `APP_ORIGIN`，没有中断已有开发服务。浏览器列表数据使用固定样本检查交互，实际 SQL 与接口兼容性由测试库集成测试验证。

分页将 Web 单页传输和渲染的人员数量限制为 25；本轮未对真实业务数据进行接口延迟基准测试，不报告未经测量的耗时降幅。
